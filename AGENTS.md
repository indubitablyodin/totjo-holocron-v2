## Overview

TOTJO Holocron v2 is a React-based Progressive Web App (PWA) for the Temple of the Jedi Order community. It provides daily practice guidance, doctrinal reading, sermon access, and a meditation timer. The app works offline-first with IndexedDB storage and syncs user data (personalization, reading progress, timer history) to Supabase when authenticated.

## Architecture Map

```
TOTJO Holocron v2
├── UI Layer (React + react-router-dom)
│   ├── src/app/ - AppShell, routing, PWA updates
│   ├── src/features/ - Feature modules (auth, library, reader, sermons, settings, timer, sync, personalization)
│   └── src/styles.css - Global styles
├── Data Layer
│   ├── IndexedDB (Dexie) - Local storage at src/lib/db/appDb.ts
│   │   ├── userPreferences, userProfile, syncState, readingHistory, timerHistory, bookmarks
│   ├── Supabase - Remote sync at src/lib/supabase/
│   │   ├── Auth: Magic link email sign-in
│   │   └── Storage: User sync profiles
│   └── Sync Engine - src/lib/sync/ - Merges local and remote state
├── Content Layer
│   ├── content/canon/ - Doctrine markdown files
│   ├── content/supplemental/ - Additional readings
│   └── content/policy/ - Policy documents
├── Service Worker (src/sw.ts) - Caching via workbox
└── Test Infrastructure
    ├── vitest - Unit tests with jsdom
    ├── Playwright - E2E tests with Chromium
    └── Test API - /api/test-sync/profile endpoint (dev only)
```

**Request Flow:**
```
Browser Request -> Vite Dev Server -> (if /api/test-sync/profile) Test Sync Middleware
                                  -> React App -> Router -> Feature Components
```

**Auth Flow:**
```
User requests magic link -> authClient.requestMagicLink() -> Supabase OTN email
User clicks link -> AuthCallbackPage -> authClient.consumeCallback() -> AuthContext sign-in
Signed in -> SyncProvider runs sync automatically on focus/online events
```

**Sync Flow:**
```
Auth state change -> SyncProvider.runSync() -> loadLocalUserSyncProfile() + loadProfile(user.id)
-> mergeUserSyncProfiles() -> saveProfile() + applyUserSyncProfile()
Triggers: auth sign-in, window focus, window online, manual retry
```

## Coding Conventions

**File Organization:**
- Features in `src/features/<feature-name>/` with co-located tests
- Feature folders contain: components, hooks, types, utils, tests
- `index.ts` files for barrel exports within features
- Test files named `<component>.test.tsx` or `<module>.test.ts`

**Naming:**
- PascalCase for components (`DoctrinePage.tsx`)
- camelCase for utilities (`readerUserState.ts`)
- kebab-case for CSS classes (`nav-link--active`)
- TypeScript interfaces/type aliases for props and complex types

**Imports:**
- Use path aliases: `@/*` resolves to `src/*`
- Group imports: external, internal (by layer), then local
- No relative imports between features (use `@/features/...`)

**React Patterns:**
- Functional components with hooks
- Context for cross-component state (AuthContext, SyncContext, ReadingSettingsContext, PersonalizationContext)
- Custom hooks for reusable logic (`useOnlineStatus`, `useAuth`)
- `react-router-dom` v7 for routing

**State Management:**
- Local component state via `useState`
- Derived state via `useMemo`
- Side effects via `useEffect`
- Sync external store via `useSyncExternalStore` (PWA updates)
- Context providers wrap feature boundaries

**Styling:**
- Global CSS in `src/styles.css`
- BEM-like class naming convention
- No CSS-in-JS or preprocessor

**TypeScript:**
- Strict mode enabled
- `esModuleInterop: true`
- `allowSyntheticDefaultImports: true`
- `jsx: react-jsx`

## Anti-Patterns and Forbidden Changes

**DO NOT:**
- Modify `node_modules/`, `dist/`, `coverage/`, `playwright-report/`, `test-results/`
- Commit secrets, API keys, or credentials
- Add dependencies without updating `pnpm-lock.yaml`
- Use `any` type (prefer `unknown` + type guards)
- Use `console.log` in production code (tests are fine)
- Modify content in `content/` without updating policy validation tests
- Change Supabase schema without updating migrations in `supabase/migrations/`
- Remove or weaken type safety
- Introduce direct DOM manipulation (use React state)
- Add synchronous side effects in component bodies
- Create circular dependencies between features

**Avoid:**
- Large files (>500 lines) - split into smaller modules
- Deeply nested folders (>3 levels from src)
- Duplicating logic across features
- Overusing Context (prefer props or composition for shallow trees)

**Test Requirements:**
- All new features must have unit tests
- All new user flows must have e2e tests
- Policy validation tests must pass for content changes
- Tests must run in CI before deployment

## Agent Workflow

### Simple Tasks

For tiny, low-risk tasks:
1. Identify the file(s) to change
2. Make the minimal change
3. Run targeted validation:
   - If touching types: `pnpm typecheck`
   - If touching styling: Visual inspection
   - If touching logic: `pnpm test` (specific test files)
4. Summarize the change

### Complex Tasks

For complex work:
1. **Plan:** Create or update `PLAN.md` with:
   - Goal statement
   - File changes (what, where, why)
   - Dependencies between changes
   - Validation strategy
   - Risk assessment

2. **Build:** One chunk at a time:
   - Edit one logical unit
   - Update `PLAN.md` with completion status
   - Run validation for that chunk
   - Commit is NOT required (user will review and commit)

3. **Validate:** After each chunk:
   - Run relevant tests
   - Verify types compile
   - Check lint passes
   - Manual testing if needed

4. **Review:** Call `oracle-review` after each chunk:
   - Provide the diff
   - Provide validation results
   - Wait for pass/fail

5. **Complete:** Do not claim completion until:
   - All chunks are done
   - Final Oracle review passes
   - Full validation sequence passes

## Stale PWA Recovery

If a user reports persistent 404s or "No routes matched location" errors after a deploy, their service worker may be serving a stale cached bundle. This can happen because the SW update cycle requires the user to close all tabs before the new SW activates.

**Recovery steps for the user:**
1. Uninstall the Holocron PWA from the device
2. Clear site data for `indubitablyodin.github.io`
3. Open `https://indubitablyodin.github.io/totjo-holocron-v2/` fresh
4. Reinstall the PWA when prompted

**Developer note:** The SW navigation denylist (PR #16) prevents future occurrences by rejecting `/imports/`, `/assets/`, and other static asset paths from being served `index.html` by the navigation fallback. If stale SW issues recur after a deploy, manually trigger a Pages deploy from `main` via: `gh workflow run deploy-pages.yml --repo indubitablyodin/totjo-holocron-v2 --ref main`
