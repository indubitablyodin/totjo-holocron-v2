# Learnings

## Architecture Insights

1. **Offline-First Design**: The app uses Dexie/IndexedDB as the primary data store. Supabase sync is opt-in via `VITE_AUTH_SYNC_ENABLED=true`. Local state always takes precedence, with remote state merged in.

2. **Test Auth Mode**: When `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are not set (or on localhost), auth automatically switches to test mode. Test mode stores auth sessions in localStorage and provides a `/api/test-sync/profile` endpoint for testing sync without Supabase.

3. **PWA with Service Worker**: `vite-plugin-pwa` generates a service worker (`src/sw.ts`) using Workbox. The PWA supports offline use and update detection via `useSyncExternalStore` in `AppShell.tsx`.

4. **Content-Driven**: Canon doctrine and supplemental content are stored as markdown files in `content/`. The `content/policy/` directory contains policy documents that have validation tests.

5. **Navigation Pattern**: Custom wheel-based navigation in `AppShell.tsx` with bottom nav for mobile. Navigation state is tracked in a ref (`inAppHistoryRef`) for in-app back button behavior.

## Non-Obvious Behaviors

1. **Auth Callback Route**: `/auth/callback` redirects to `/settings` in the route config, but `AuthCallbackPage` handles the actual OAuth callback logic before redirecting.

2. **Sync Triggers**: Sync automatically runs on:
   - Auth state change (sign-in/sign-out)
   - Window focus event
   - Window online event
   - Manual retry via `retrySync()`

3. **Test Sync API**: The dev server provides a REST API at `/api/test-sync/profile` for e2e testing sync behavior without Supabase. Methods: GET (load), PUT (save), DELETE (clear).

4. **GitHub Pages Base URL**: When `GITHUB_PAGES=true`, `getBasePath()` in `vite.config.ts` sets the base to `/<repo-name>/`. The service worker and routing account for this.

5. **Policy Validation**: Content in `content/policy/` is validated by tests in `tests/policy-validation.test.cjs`. Changes to policy content must pass these tests.

## Debugging Tips

1. **Playwright MCP**: The `.playwright-mcp/` directory contains saved page states from Playwright test runs. These are git-ignored but can be useful for debugging test failures.

2. **Sisyphus**: The `.sisyphus/` directory is used for test state persistence (see `testSyncStorePath` in `vite.config.ts`).

3. **Dev Tools**: The app exposes a test sync API endpoint during development. Use `curl` or browser to interact with `/api/test-sync/profile?userId=...`

4. **Auth Test Mode**: Set `VITE_AUTH_TEST_MODE=true` to force test auth even with Supabase configured. Useful for local testing without email.

5. **Offline Testing**: The app detects offline state in `AppShell.tsx` and shows a banner. Use browser dev tools to simulate offline mode.

## Gotchas

1. **BrowserRouter basename**: The production app uses `basename={import.meta.env.BASE_URL}`. In GitHub Pages deployment, this is `/totjo-holocron-v2/`. Links must account for this.

2. **Sync in Test Mode**: Test auth mode works, but sync requires `VITE_AUTH_SYNC_ENABLED=true` AND Supabase to be configured. Without both, sync runs in local-only mode.

3. **Dexie Schema**: The IndexedDB schema is defined in `src/lib/db/appDb.ts`. Schema changes require migration logic or clearing the database.

4. **React 19**: The project uses React 19.2.0 which has some API differences from React 18 (e.g., `use` hook, automatic batching changes).

5. **Vite Test Middleware**: The `testSyncApiPlugin` in `vite.config.ts` only works in dev/preview mode, not in the production build.

## Performance Notes

1. **Large CSS File**: `src/styles.css` is ~44KB. Consider splitting or using CSS-in-JS if this grows significantly.

2. **AppShell Complexity**: `AppShell.tsx` is ~500 lines with complex navigation logic. This is a candidate for splitting if it grows more.

3. **Sync Merge Logic**: Profile merging in `src/lib/sync/` uses timestamp-based conflict resolution (last write wins). This is simple but may need refinement for complex merge scenarios.
