# Validation

Generated by /prep on 2025-05-01.

## Validation Commands

| Type | Command | Time | When to Run |
|------|---------|------|--------------|
| Lint | `pnpm lint` | ~5-10s | After any code change |
| Typecheck | `pnpm typecheck` | ~10-15s | After type/interface changes |
| Unit tests | `pnpm test` | ~20-30s | After logic changes |
| Build | `pnpm build` | ~15-25s | Before deployment |
| E2E tests | `pnpm test:e2e` | ~1-2min | Before major releases |

## Full Validation Sequence

```bash
# Standard sequence (local development)
pnpm lint && pnpm typecheck && pnpm test

# Full CI sequence
pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm test:e2e

# Quick feedback loop
pnpm typecheck && pnpm test
```

## Targeted Validation

### By File Type

| Changed Files | Recommended Validation |
|---------------|------------------------|
| `*.ts`, `*.tsx` | `pnpm typecheck` + affected unit tests |
| `*.css` | Visual inspection, lint |
| `*.json` (config) | Build, lint |
| `content/**` | `pnpm test` (policy validation) |
| `src/lib/db/*` | Unit tests for db, full test suite |
| `src/lib/sync/*` | Sync tests, e2e sync tests |
| `src/features/auth/*` | Auth tests, e2e auth tests |

### By Change Type

| Change Type | Validation |
|-------------|------------|
| Type signature change | `pnpm typecheck` + all dependent tests |
| Logic change | Unit tests for that module |
| UI change | Visual inspection + e2e tests |
| Routing change | Navigation e2e tests |
| Sync logic change | Sync unit tests + e2e sync tests |
| Content change | Policy validation tests |
| Dependency update | Full validation sequence |

## Test Patterns

### Common Test Utilities

**AppTestRouter** (`src/app/AppRoutes.tsx`):
- Wraps components with MemoryRouter for testing routed components
- Includes all providers (Auth, Sync, Personalization, ReadingSettings)

```typescript
<AppTestRouter initialEntries={['/daily']}>
  <MyComponent />
</AppTestRouter>
```

**Test Sync API** (dev only):
- Available at `/api/test-sync/profile` during dev server
- Allows testing sync without Supabase

### Auth Testing

Test auth is automatically enabled without Supabase config:

```typescript
// Test mode is auto-enabled on localhost without Supabase
const client = createAuthClient();
// client.mode === 'test'

// Force test mode
process.env.VITE_AUTH_TEST_MODE = 'true';
```

### Sync Testing

Sync requires both test auth AND sync enabled:

```typescript
process.env.VITE_AUTH_TEST_MODE = 'true';
process.env.VITE_AUTH_SYNC_ENABLED = 'true';
```

## CI Pipeline

### GitHub Actions Workflows

**CI (`.github/workflows/ci.yml`):**
```yaml
Jobs:
  verify:
    - Checkout
    - Setup pnpm + Node 22
    - Install dependencies
    - Install Playwright browsers
    - Lint
    - Typecheck
    - Unit tests
    - Build
    - E2E tests
```

**Deploy Pages (`.github/workflows/deploy-pages.yml`):**
```yaml
Jobs:
  build:
    - Checkout
    - Setup pnpm + Node 22
    - Install dependencies
    - Unit tests
    - Typecheck
    - Build (with GITHUB_PAGES=true)
    - Upload artifact
  deploy:
    - Deploy to GitHub Pages
```

## Writing New Tests

### Unit Test Template

```typescript
// src/features/xxx/xxx.test.tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { describe, expect, it, vi } from 'vitest';
import { AppTestRouter } from '@/app/AppRoutes';
import { MyComponent } from './MyComponent';

describe('MyComponent', () => {
  it('renders correctly', () => {
    render(
      <AppTestRouter initialEntries={['/my-route']}>
        <MyComponent />
      </AppTestRouter>,
    );
    
    expect(screen.getByText('Expected text')).toBeInTheDocument();
  });
});
```

### E2E Test Template

```typescript
// tests/e2e/xxx.spec.ts
import { test, expect } from '@playwright/test';

test('my feature works', async ({ page }) => {
  await page.goto('/my-route');
  await expect(page.getByText('Expected text')).toBeVisible();
});
```

## Validation Checklist

Before committing:
- [ ] `pnpm lint` passes
- [ ] `pnpm typecheck` passes
- [ ] Relevant unit tests pass
- [ ] Manual testing in dev server
- [ ] No console errors/warnings

Before pushing:
- [ ] All of the above
- [ ] `pnpm test` passes
- [ ] `pnpm build` succeeds

Before merging:
- [ ] All CI checks pass
- [ ] E2E tests pass (if changed functionality)
