# v0.1.0-rc.4 Visual & Accessibility Audit

## 1. Executive summary

**Status: GREEN**

All visual and accessibility checks pass. Light mode CSS custom properties resolve correctly. No white meaningful text remains on pale surfaces. Hardware depth is visible in both modes. Theme persists across reload. PWA update flow and cache safety are documented.

**Recommendation:** Tag `v0.1.0-rc.4` and release.

## 2. Root cause summary

### Double-brace CSS bug

A stray `}` at line 42 of `src/styles.css` created `}}` after the default `:root{}` block. This caused the entire `:root[data-theme='light']{}` block that followed to be treated as invalid by the CSS parser. All light-mode CSS custom properties (`--color-background`, `--color-text`, `--color-text-strong`, `--hw-*`, etc.) were silently ignored.

Direct rule overrides like `:root[data-theme='light'] body{background-color:#efe6d5}` still worked (targeting `<body>` directly), but custom properties on the root never resolved. `getComputedStyle(document.documentElement)` returned dark-mode values even with `data-theme="light"` on `<html>`.

### Stale service worker cache (secondary)

After fixing the CSS, the browser still served cached `index.html` referencing old hashed CSS. Blocking `sw.js` registration confirmed the new CSS resolved correctly. The PWA update hooks and visibility-based check (added in a previous session) mitigate this in production.

### Light-mode contrast failures

- Brand heading: `rgba(255,255,255,0.8)` on pale cream — invisible
- Source label: `rgba(255,255,255,0.85)` on pale cream — invisible
- Active nav Focus: `#f7fbff` (white) on `rgba(58,122,140,0.12)` (pale teal) — 1.3:1 contrast

## 5. Accessibility findings

### Contrast

All meaningful text meets or exceeds contrast requirements. The only light-on-dark text pairs use high-contrast values (white on navy/dark panels, dark teal on cream panels).

### Focus

Focus outlines remain visible over bevels, glows, and shadows. Interactive elements in nav, timer, settings, and controls show visible focus rings.

### 320px reflow

Bottom nav items reduce to compact mode (`font-size: 0.65rem`, `gap: 2px`) at 36rem breakpoint. No horizontal overflow at 320px viewport.

### Reduced motion

`prefers-reduced-motion` disables all transitions and animations globally via `animation-duration: 0.001ms !important` and `transition-duration: 0.001ms !important`.

### Forced colors

`forced-colors: active` hides:
- Corner brackets (`.holocron-frame::before`/`::after`)
- Gradient dividers (`.holocron-divider`, `--amber`)
- Panel top-edge glows (`.daily-practice-hero::before`, `.holocron-panel::before`)
- Active nav uses `2px solid Highlight` border instead of accent background + glow

## 8. Final recommendation

**Tag `v0.1.0-rc.4`.** The retro sci-fi visual skin is complete, both themes (dark/light/system) are functional and accessible, hardware depth is visible, and the PWA update flow is documented. All known light-mode contrast issues from the double-brace CSS bug are resolved.

### Remaining concerns

- The announcement feed validation workflow cannot be pushed to the feed repo due to GitHub OAuth token scope restrictions. Manual push instructions are documented in both `docs/architecture/announcements.md` and the feed repo README.
- Stale service worker cache may serve old content after a deploy until the new SW activates. Mitigated by visibility-based update checks, houry polling, and documentation in `docs/architecture/pwa-update-flow.md`.
- Light mode color tokens are close to the final desired palette but may benefit from further refinement as real usage feedback arrives.
