# Known Issues and Fix History

Purpose: a single place to check *before* touching nav, timer, announcements, or CSS in this
codebase, so the same bugs don't get reintroduced. Written for whoever (human or AI) picks this
project up without the context of how each of these was found. Last compiled 2026-09-09.

If you fix something that took real investigation to understand, add it here — a two-line commit
message six months from now is not enough context for the next person.

## Patterns worth knowing before you touch these areas

- **`styles.css` cascade bugs are the single most common regression class in this project.** At least three separate bugs (nav font-shrink, announcement-badge overlap, field-card layout) were caused by a *later* rule in file order silently winning over an earlier, more specific-looking one, at equal CSS specificity. Before editing a class here, `grep -n "\.your-class-name"` for **every** occurrence in the file, not just the first one you find — this file is ~95KB, single global stylesheet, no CSS Modules, and the same class name is legitimately redefined in multiple theme/skin sections.
- **Three timer surfaces share one `TimerPreferences` object but have three separate UI implementations**: Settings > Timer Defaults (`SettingsPanels.tsx`), the full Timer page (`TimerPage.tsx`), and the dashboard widget (`TimerCore.tsx`/`TimerSettingsPanel.tsx`). They were unified in intent (2026-09-09, `8a075af`) but remain three separate components — a new timer-preference field added to one needs to be considered for the other two, there's no shared form component enforcing this.
- **Two systems both use "update"/"app update" language for unrelated things**: the PWA service-worker update banner (new app code) and the Announcements system (content notices, one `kind` of which is literally `'app'`). See the disambiguation sections added to both architecture docs.
- **Contract docs (`docs/ux/mobile-first-ia-contract.md`, the ADRs in `docs/adr/`) are not enforced by any test or CI check.** They can and have drifted from the code silently. Treat them as intent, verify against `AppShell.tsx`/the actual component before trusting a "locked" claim.
